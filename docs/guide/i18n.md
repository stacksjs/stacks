# Reactive translations

A language choice should update the mounted screen, including labels, dates and
errors. It should preserve the user's draft and completed actions. Stacks offers
a browser-safe translator and a native STX composable for this purpose.

```ts
import { useI18n } from '@stacksjs/i18n/stx'

export const words = useI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: {
    en: { verified: 'Email verified', sessions: 'no sessions | one session | {count} sessions' },
    de: { verified: 'E-Mail bestätigt', sessions: 'keine Einheiten | eine Einheit | {count} Einheiten' },
  },
})
```

Bind text through STX, for example `<p :text="words.t('verified')"></p>` and
`<p :text="words.tc('sessions', 2)"></p>`. Calling `words.setLocale('de')` updates
these bindings in place. It also updates reactive reads of `words.locale`,
`words.n(...)`, `words.d(...)`, `words.te(...)` and `words.tm(...)`. Existing
server-rendered interpolation is not automatically a reactive client binding.

Keep one instance shared by the modules of a screen. The application persists
the preference in its cookie or account, updates document language metadata,
and handles account-save failures. Update the UI before awaiting a network
save. Do not reload, fetch a replacement HTML page, or repeat a completed
verification operation to change a language. Use buttons for local controls,
with reactive `aria-pressed` state and accessible labels.

Use `words.addTranslations(locale, messages)` for lazy catalogs. This updates
bindings too. `words.subscribe(listener)` returns an unsubscribe function for
optional observers; selecting the current locale does not notify again.

For browser code without STX, import `createI18n` from
`@stacksjs/i18n/client`. It exposes the same translator and Intl helpers without
filesystem or application-configuration dependencies. Use the root server entry
for file loaders and request-locale helpers. Create an isolated translator per
independent server request rather than changing a process-wide locale.

Text and plurals fall back from a regional locale such as `de-DE` to `de`, then
to the configured fallback locale. A missing key can use `missingHandler` or
return the key itself. See the [i18n skill](/skills/domain/i18n) for formatting,
plural rules, typed catalogs and server request integration.
